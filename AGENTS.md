# Project Rules

1. Create a GitHub issue only after the user's requirement is confirmed and the
   program has a corresponding code change. Reviews, inspections, and changes
   that do not modify the program do not require an issue.
2. After the program change is complete, reply to the issue with a summary of
   what changed, then set its status to `verify` or another non-`open`,
   non-`closed` status.
3. Every change submitted through a GitHub issue must include a version bump.
